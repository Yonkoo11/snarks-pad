# Port assumptions: Raydium LaunchLab -> Meteora DBC (+ DAMM v2, Squads v4)

First written 2026-10-01 BEFORE the rest of the port, by the agent resuming an interrupted draft; re-checked and rewritten at the end of the same day. Every row says what the engine assumes and is VERIFIED (a source file:line, an on-chain read, or a named test that ran and passed), FIXED (it was wrong in the draft, now corrected and tested), a DECISION (a choice, with the reason), or a DOCUMENTED LIMITATION. **No row in a money path is UNVERIFIED**; the last section lists what is genuinely not verified and why none of it is a money path of this build.

Source roots:
- `DBC` = `probe/meteora-dbc/vendor/program/programs/dynamic-bonding-curve/src` (MeteoraAg/dynamic-bonding-curve @ f552f20)
- `DAMM` = cp-amm `programs/cp-amm/src` (MeteoraAg/damm-v2 @ a85c926)
- `SQ` = Squads v4 `programs/squads_multisig_program/src` (Squads-Protocol/v4 @ af94153)
- `SDK-DBC` = `engine/node_modules/@meteora-ag/dynamic-bonding-curve-sdk/dist/index.js` (1.5.13); `SDK-CP` = `@meteora-ag/cp-amm-sdk/dist/index.js` (1.5.1)
- "live test" = a test in `engine/test/` that runs against the local validator, which executes the MAINNET DBC, DAMM v2 and Squads v4 binaries with the real ZEC mint and the DAMM v2 1% config cloned from mainnet. Test names below are file names; `bun test` ran 234 tests (twice), 0 failures, and `bun run e2e` 50/50 checks on 2026-10-01 after the NEAR 1Click leg (sections 6b, 6c) was added.

Assumptions that turned out WRONG, in one place: **N1** (the 1Click origin asset id: the engine used `nep141:sol-a7bd...omft.near`, which the live API rejects; the id is `1cs_v1:sol:spl:<mint>`), **N8** (1Click's reported `amountOut` is not what the treasury receives: 368,000 vs 375,000 in F-030), the old adapter's mapping of `REFUNDED`/`FAILED` to "pending forever", and the engine's reading of any `submit()` rejection as "no funds moved" (S2 H2), **S1** (token-account rent is 1,488,440 lamports on mainnet and devnet, 2,039,280 on a local validator; the plan, F-036 and the draft used the local number), **D16** (the SDK's surplus claim pays the fee claimer's own account, not the keeper's), **D17** (the draft treated any non-zero `migration_progress` as "curve full"), **D15** (partner surplus is ~0 with this curve, so it is not worth a claim), **E2** (the draft could finalize or discard an epoch while a claim was in flight), **Q6** (the Squads memo is not stored on chain). The seed's "wallet with no ZEC account" also landed above the new-account threshold (31,768 zats vs 30,000) and was paid instead of carried; the e2e caught it and the seed now sends a sixteenth of the tokens.
